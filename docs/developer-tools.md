# Developer tools

## Shell

`tasks/shell.py` keeps your `~/.bashrc` and only adds marked blocks to it. The Bash parts live in
`~/.config/bash/`:

- `grml.bash`: a grml-style prompt, `autocd`, spelling fixes for `cd`, `globstar`, the grml
  aliases (`l`, `la`, `ll`, `..`, ...), and a directory stack (`cd -2` jumps back two dirs).
- `history.bash`: 100,000 lines with timestamps, shared between all open terminals right away.
- `readline.inputrc`: type the start of a command, then Up/Down searches history by that prefix.
- Completions for kubectl (and the `k` alias), helm, gh and rc, generated from the installed
  tools.
- `dl` is `aria2c` with 16 connections, resume and retries (`~/.config/aria2/aria2.conf`).
- nano gets line numbers, mouse support, soft wrap and syntax highlighting.
- Neovim gets [nvim-simple](https://github.com/norandom/nvim-simple): CUA keys, a menu bar and
  pinned plugins (NERDTree, airline, quickui, devicons).

`shell_blesh = true` adds [ble.sh](https://github.com/akinomyoga/ble.sh): zsh-like inline
suggestions, syntax colours and a completion menu. Its settings are in
`~/.config/bash/blerc`. `false` and a re-run take it out of `~/.bashrc` again.

`shell_interactive = "fish"` makes [fish](https://fishshell.com) the shell in every terminal
(Terminator, foot, Ghostty, xfce4-terminal, editor terminals). Bash stays the login shell:
`~/.bashrc` runs as before and hands over to fish at its first prompt, so PATH, `CC`, nvm's
Node and the alerts carry over. The grml aliases become fish abbreviations (`ll` expands to
`ls -l` as you type), `mkcd`, `cdt`, `bk`, `sll`, `ssearch`, `cd -N`, the prompt, safe-chain
and the GCC guard for package builds come along (`~/.config/fish/conf.d/t2-mac-kde.fish`;
your own settings go in `~/.config/fish/config.fish`). ble.sh is skipped while fish is on.

- `bash` in fish gives you bash (no hand-over back); `T2_NO_FISH=1` keeps a terminal in bash.
- Scripts and `bash -c` never change; write them in bash as before.
- `nvm` runs through bash, so `nvm use` doesn't stick in fish: the default Node from
  `~/.bashrc` applies, or run `bash` for a session on another version.
- `"bash"` (default) and a re-run of `tasks/shell.py` remove it again.

What fish adds on top:

| Feature | How |
|---|---|
| Suggestions as you type, syntax colours, completion menu | built in; → accepts a suggestion, Alt+→ one word |
| Completions for every tool with a man page | generated once at deploy; `fish_update_completions` refreshes them |
| Fuzzy search | Ctrl+R history, Ctrl+T insert a file, Alt+C change into a directory (fzf) |
| Long commands | right side of the prompt shows the time from 2 s on |
| Done notification | a command that ran 30 s or more and whose terminal isn't focused ends with a notification (exit code, duration); editors, pagers, SSH and other interactive tools never notify. Threshold: `set -U t2_done_after 60000` |
| Your bash history | imported once, when fish has no history yet |
| Colours | follow the terminal palette (SUPER+Y, `hypr-termtheme`); open fish windows repaint at once |
| Built-in keys | Alt+S puts `sudo` in front, Alt+E edits the line in `$EDITOR`, Alt+H man page of the command, Alt+←/→ directory history, `cdh` directory list |

`shell_prompt = "starship"` switches bash and fish to the [Starship](https://starship.rs)
prompt (Ubuntu package): the same layout as before (exit code, user@host, directory, git) plus
symbols for the language or tool of the directory you're in, e.g. ` 3.14.4 (.venv)` next to a
`pyproject.toml`, ` 26.13.1` next to a `package.json`, Rust, Go, Nim, C, Java, Lua, Ruby,
Zig, Deno, Bun and Nix shells; the command duration sits on the right. One config for both
shells, `~/.config/starship.toml`, generated by `tasks/shell.py` with the five terminal
palettes; SUPER+Y switches the palette from the next prompt on. The icons come from FiraCode
Nerd Font (fontconfig fills them in for the Berkeley Mono and Fixedsys profiles). `"builtin"`
(default) brings back the grml prompt.

## Compilers

GCC and make come from Ubuntu, and GCC is the compiler everywhere: C and C++, Go with cgo,
the C parts of Rust crates (cc-rs, cmake-rs), Nim and V. Builds then link only against the
system's libraries, so what you ship runs on a normal Ubuntu.

Intel's oneAPI `icx`/`icpx` are installed from Intel's apt repo (`tasks/vendor_apps.py`) but
stay off your PATH. Use them for one command when you want them:

```sh
intel make                  # CC=icx CXX=icpx for this command only
intel cmake -B build && intel cmake --build build
intel go build              # cgo through icx
nim-icx c -d:release app.nim
v -cc icx .                 # V picks its compiler with -cc
```

Rust crates compiled with icx need Intel's runtime library (`_intel_fast_memcpy`), which rustc
doesn't link, so `intel cargo build` usually fails at the link step; keep GCC for Rust.

The system never sees icx: root, sudo, apt and the package helper keep GCC, `dpkg-buildpackage`
and `debuild` are wrapped to force GCC, the kernel build picks its own compiler, and if DKMS is
ever installed a drop-in unsets CC/CXX for it, even under `sudo -E`.

## Desktop app build libraries

`tasks/dev_libs.py` installs the headers for GTK/WebKit desktop apps (Tauri, e.g. the 1-1 RDP
client): `libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`,
`libdbus-1-dev`, `libssl-dev` and `pkg-config`. Turn it off with `dev_libs = false`.

The same task installs Qt 6 for C++, QML and Python: Qt Creator (with clangd and clang-tidy),
the Qt 6 headers and tools, CMake and Ninja, PyQt6 (`pyuic6`) and PySide6 (`pyside6-uic`,
`pyside6-designer`). Everything is from the Ubuntu archive, so what you build links against
the system's Qt.

Use the Ayatana tray headers, not `libappindicator3-dev`: the legacy package conflicts with the
Ayatana library that nm-applet and 1-1 need, and `apt install libappindicator3-dev`
removes both. If the legacy pair is installed, the deploy replaces it and later tasks put
the tray apps back. pkg-config knows the Ayatana library as `ayatana-appindicator3-0.1`; Tauri
finds it under that name.

## Node and Python

- Node comes from nvm, per user, at the version in `.nvmrc`. No system Node, no npm prefix

## Safe Chain

```toml
safe_chain = true
```

Installs Aikido Safe Chain (`@aikidosec/safe-chain`, pinned) and aliases
`npm`, `npx`, `yarn`, `pnpm`, `pnpx`, `bun`, `bunx`, `pip`, `pip3`, `pipx`, `uv`, `uvx` and
`poetry` to its wrappers, which check packages for known malware before installing them. Its own
`safe-chain setup` isn't used, so your shell profiles aren't rewritten.

## Containers

`tasks/containers.py`:

- Docker Engine from Docker's apt repo (key pinned by sha256): `docker`, `docker compose`
  (plugin), `docker buildx`, and a `docker-compose` link to the plugin. It replaced rootless
  Podman on 2026-11-25; the Podman packages, podman-tui and Podman Desktop are removed.
- Not Docker Desktop: on Linux that runs its own VM with a separate engine.
- The daemon is socket-activated: it starts with the first `docker` command, not at boot.
  Containers with a restart policy come back once the daemon runs; `sudo systemctl enable
  docker.service` starts it at boot instead.
- You're in the `docker` group, which is root-equivalent (applies at the next login).
- `/etc/docker/daemon.json`: `ip-forward-no-drop` (otherwise Docker sets the FORWARD policy to
  DROP and libvirt's VM networks lose their connection) and container logs capped at 3 × 10 MB.
- `lazydocker` (Nix) is the terminal UI; `ctop` (Nix) shows live CPU, memory and I/O per container.

## Virtual machines

`tasks/virtualization.py` installs virt-manager on KVM with QEMU, OVMF (UEFI) and swtpm (a virtual
TPM, enough for Windows 11). Your user joins the `libvirt` group (next login), and libvirt's
default NAT network is started at boot. Guests use the host's route, including a Tailscale exit
node when one is on. Nested virtualization is already the kernel default; KVM is told to ignore
unknown MSRs so Windows guests with Hyper-V or WSL2 don't crash.

## iOS apps with xtool

[xtool](https://github.com/xtool-org/xtool) replaces Xcode for building and deploying iOS apps
with SwiftPM. The deploy unpacks the pinned AppImage into `~/.local/opt/xtool-<version>` (no
FUSE 2 needed) and links `xtool` into `~/.local/bin`. Once:

```sh
xtool setup     # Swift toolchain check, Apple Developer login, Darwin SDK from your Xcode.xip
```

You need an Apple ID and a downloaded `Xcode.xip`; xtool extracts the SDK from it. Then
`xtool new`, `xtool dev` build and run on a connected iPhone.

## Housekeeping

`dev-disk-reclaim` lists regenerable caches (Podman and Docker, build dirs in `~/.cache`) and
deletes them only with `--apply`. `t2-alerts` shows SSD health and service alerts, which new
shells also print until you `t2-alerts ack`.

## File icons, Rust utilities and multiplexer keys

The default Nix tools include lftp, byobu, eza and uutils-coreutils. Interactive fish
uses the prefixed Rust utilities via aliases while keeping fish builtins; `command cp`
(or `/usr/bin/cp`) bypasses the alias. System scripts keep the distro utilities.
`ls` uses eza with file icons when installed, including the existing `ll`/`la` abbreviations.
Use a Nerd Font in the terminal for icons. Starship controls the prompt, not file listings.

`tasks/multiplexers.py` configures Zellij and Byobu's tmux backend with Ctrl+A as the
prefix: `c` new window/tab, `n`/`p` next/previous, `d` detach, `[` scrollback,
`s`/`v` split down/right, Tab next pane, `a` send Ctrl+A (beginning of line).
Zellij scrollback: arrows or Ctrl+P/N, PageUp/Down or Alt+V/Ctrl+V; q/Esc exits.
Byobu uses Emacs copy-mode keys. Existing config is backed up; start a new session
after deploying. Other Emacs control keys pass through to applications.

Deploy these changes as the desktop user:

```sh
.venv/bin/pyinfra @local tasks/nix_tools.py --use-sudo-password
.venv/bin/pyinfra @local tasks/shell.py --use-sudo-password
.venv/bin/pyinfra @local tasks/multiplexers.py
```

## Navigation, local history and command headers

The default Nix profile now includes Atuin, delta, Yazi and zoxide. In a fresh fish
session, Ctrl+R searches Atuin history, Up keeps fish's normal behavior, `z`/`zi`
jump to known directories, `y` opens Yazi and follows its selected directory on
exit, and `ff` searches files with a bat preview. Git uses delta with ANSI colours
that follow the terminal palette. These integrations are installed by tasks/shell.py.

Atuin is configured with auto_sync=false, update_check=false, daemon disabled,
and a loopback-only sync address. Fish enforces these through ATUIN environment
variables before initialization. There is no account creation, login, history import
or sync operation in deployment. History remains on this laptop. This is an
application configuration policy, not an OS network sandbox; manually overriding
it or launching Atuin with other configuration can change the policy.

## Terminator pinned command prototype (disabled)

The owner disabled this prototype to move it into a separate project. Theme deployment
removes CommandHeader from enabled_plugins while preserving other plugins. Shell deployment
removes the active command-header hooks and restores ordinary directory titles.
Restart Terminator/fish after deploying. To disable a currently running instance immediately,
uncheck CommandHeader in Preferences → Plugins; its unload handler restores terminal input.

The inactive source is retained in files/themes/terminator/plugins/command_header.py and
command_header.fish for extraction. Neither file is deployed by this project now.
Previously deployed plugin files may remain on disk but are disabled.

Warp was removed from provisioning at the owner's request. tasks/remove_warp.py,
included in deploy.py, removes the exact previously managed user-level payload,
launcher, desktop entry and marked settings/themes. User-created Warp data and
pre-t2 settings backups are retained. No Warp installation or theme target remains.

## Cyberterm 2077 (formerly Warpeer)

`tasks/warpeer.py` installs [Cyberterm 2077](https://github.com/norandom/Cyberterm-2077), our
terminal fork that was called Warpeer until v1.0.0, from release `v1.0.1` under
`~/.local/opt/cyberterm2077-v1.0.1`, with a `~/.local/bin/cyberterm2077` command and
application-menu entry. Both the archive and executable are SHA-256 pinned. This task needs
no sudo or package changes and is included in `deploy.py`. The proprietary Warp cleanup
remains separate.

```sh
.venv/bin/pyinfra @local tasks/warpeer.py --dry
.venv/bin/pyinfra @local tasks/warpeer.py
```

The rename changed the release, the executable and the menu entry only. Data stays in the
`warpeer` directories (`~/.config/warpeer`, `~/.warpeer`, `~/.local/state/warpeer`), so
preferences carry over; the task, `manage/warpeer.py` and the config key `warpeer_font` keep
the old name too. The deploy removes the old `warpeer` command and menu entry. Older
`~/.local/opt/warpeer-*` version directories are left in place; delete them by hand when you
no longer want them.

The fork merges Warp upstream directly while staying terminal-only: no sign-in, telemetry,
crash reporting, hosted AI or sync. Once a day it asks the project's GitHub Releases whether a
newer signed version exists and installs it only when you click to apply it. An update applied
that way no longer matches the pin, so the next deploy puts the pinned version back; change
the release and hashes in the task to move the pin. The Linux binary requires glibc 2.39 or
newer.

Cyberterm 2077 selects the configured `shell_interactive` as its native startup shell.
The managed Bash-to-fish prompt handover is disabled when `TERM_PROGRAM` is
`WarpTerminal`: replacing the shell after bootstrap discards its command
hooks and can hide command output. Existing appearance preferences are
preserved; open a fresh session after changing the startup shell.

Input is pinned to the top (Reverse mode), with command blocks below it,
using `appearance.input.input_mode = "pinned_to_top"`.

The command palette has **Add local runbook folder** and **Browse local runbooks** to
It searches user-selected folders for Markdown documents;
opening a document does not execute commands. Use a shell block’s explicit Run
control. Folders remain local and are stored under `[runbooks]` as a `folders`
list in `~/.config/warpeer/settings.toml`. No YAML workflows or cloud sync are enabled.

The managed font is **Fixedsys Excelsior**, installed by `tasks/fonts.py`.
`warpeer_font` overrides this family. Terminal/editor text, document text and
menus/tabs use the same family; existing font sizes are preserved.

The toolbar adds **New Window**, **New Tab**, **New File**, and **CP** before the
existing right-side controls. CP opens the command palette (Ctrl+Shift+P), and
its hover label is **Command Palette**. Save a new Markdown file with Ctrl+S in
one of your configured runbook folders.

**Settings → Appearance → Text → Enforce minimum contrast** is managed as
**Always** (`appearance.text.enforce_minimum_contrast = "always"`). This also adjusts
explicit RGB shell colours in command history against the active background when
switching between light and dark themes. Underlines remain; low-contrast colours
may shift for readability.

`files/warpeer/settings.toml` holds the repository defaults captured from the owner's
preferences: Neobones Light, compact vertical tabs, Fixedsys 16, steady block cursor,
and terminal animations. Deployment fills missing settings while preserving existing
choices (including later theme changes and local runbook folders). Shell, font,
pinned input, automatic contrast and fully opaque windows with no blur remain managed.
No session history or machine-specific paths are included.
